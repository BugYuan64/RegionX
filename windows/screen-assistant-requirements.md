# RegionX · 需求文档

## 1. 项目概述

一个桌面区域识别工具。用户打开后，屏幕上出现一个透明、可自定义大小的识别框，框内的内容可以被软件中配置好的 AI 模型处理，包括回答题目、翻译、提取文字。

- 先做 **Windows 版**，再做 **Android 版**
- 两个平台采用**不同的架构**，让每个平台上都尽量轻便
- 模型接口可自定义，通过 **LLM Gateway** 统一接入

---

## 2. Windows 版

### 2.1 整体结构

| 部分 | 说明 |
|---|---|
| 主程序 | 常驻程序，包含历史会话列表和"开始"按钮，所有任务和历史都保存在这里 |
| 识别框 | 主程序的子窗口，透明、可移动、可缩放 |
| 工具栏 | 贴在识别框外下侧，横排 6 个按钮 |
| 任务队列 | 贴在识别框外左侧，竖排显示当前会话的任务 |

### 2.2 主程序界面

- **历史会话**占据窗口的大部分面积
- **"开始"按钮**位于屏幕内靠下方
- 每个**会话**对应一次打开识别框所创建的任务队列
- 点开任意会话，以**下拉框**形式向下展开，列出该会话队列里的每个任务：
  - 任务标题（10 字以内）
  - 标题下方一行小号文字简介（20 字以内）
- 点击某个任务，跳转到任务详情页，显示：
  - 当时截取的图片
  - 我选择的操作（回答 / 翻译 / 提取图文）
  - AI 的回复
  - 页面最下方有**输入框**，可对 AI 进行二次追问
- 点击"开始"，打开识别框

### 2.3 识别框

- 透明，可以看到叠在它下面的桌面内容
- 可移动、可自定义大小
- **只有点击"退出"按钮才会关闭**，其他操作都不会关闭
- 关闭时只是隐藏窗口，任务队列保留在主程序中
- 再次点击"开始"，重新打开识别框，并创建一个新的会话

### 2.4 下侧工具栏（横排，共 6 个按钮）

1. **回答**：截取框内区域，识别并回答其中的题目或问题
2. **翻译**：截取框内区域，翻译其中的文字
3. **提取图文**：截取框内区域，只提取文字（OCR）
4. **模型切换**：在已配置的模型之间切换
5. **置顶窗口**：切换识别框的置顶状态
6. **退出**：关闭识别框

### 2.5 左侧任务队列（竖排）

- 显示当前会话里的所有任务
- 点击回答 / 翻译 / 提取图文中的任何一个按钮，都会生成一个任务并加入队列
- 每个任务卡片显示状态（排队中 / 处理中 / 已完成 / 失败）和结果
- 结果流式显示，支持取消和重试

### 2.6 点击按钮后的流程

1. **立即截取**框内区域，保存为该任务自己的图片，之后框怎么移动或缩放都不影响这个任务
2. 生成任务，字段包括：`id`、`类型`、`图片`、`区域`、`状态`、`结果`、`时间`
3. 加入队列，后台异步处理，同时最多并行 2 到 3 个任务
4. 用户可以接着移动识别框，对下一道题再点击按钮，不需要等上一个完成

### 2.7 数据与历史

- **历史需要永久保留**（退出程序后仍然存在）
- 保存内容：会话、任务、截图、AI 回复、追问记录
- 建议用本地 SQLite（或 JSON）保存结构化数据，截图保存为本地图片文件

### 2.8 模型接口

- 支持自定义配置
- 支持的接口类型：**OpenAI 兼容接口、Claude、Gemini**
- 通过 **LLM Gateway** 统一调用，上层不关心具体厂商
- 模型切换按钮从已配置的模型列表中选择

## 4. 技术注意点（Windows）

- **截图时排除自身**：识别框边框、工具栏、任务队列都不能出现在截图里（如 `SetWindowDisplayAffinity` / Electron 的 `setContentProtection`）
- **工具栏和任务队列跟随识别框**：识别框移动或缩放时同步更新位置，靠近屏幕边缘时自动调整位置
- **框内鼠标穿透**：框内区域不拦截鼠标，只有边框和缩放手柄接收鼠标操作
- **子窗口关系**：识别框是主程序的子窗口，主程序退出时识别框一并退出

# 6. 追加需求（2026-10-28，UI 方案版）

本节为在 UI 方案确定后新增/细化的需求，与前文冲突时以本节为准。

### 6.1 UI 方案

界面按根目录《RegionX UI 方案.html》实现，包含三块：

- **主程序 · 历史会话**：深色界面（背景 `#17181C`，面板 `#1D1F24`、`#212328`、`#2A2D33`，琥珀色点缀 `#FFB224`），自定义标题栏，居中最大宽度 880px 的内容区，会话为可折叠卡片，任务行为「图标 + 标题 + 一行简介 + 状态 + 时间」，底部为大号「开始识别」胶囊按钮。
- **任务详情 · 追问**：左侧为当前会话的任务列表，右侧为详情；顶部标题行含操作类型徽章、模型名与时间；内容区依次为截图、我的要求、AI 回复、追问对话轮次；底部为追问输入框与圆角发送按钮，并带「追问时附带原截图」勾选项。
- **识别框 · 工具栏 · 任务队列**：识别框为琥珀色 2px 边框、带四角 8 个手柄、上方悬浮尺寸标签；工具栏为深色圆角横条，6 个「图标 + 文字」竖排按钮，当前操作高亮为琥珀色；任务队列为深色圆角面板，标题行显示会话时间与任务数，任务卡片以状态圆点区分（完成绿 `#5FD39A`、处理中琥珀、排队中灰、失败红 `#FF7A72`）。

界面配色、字号、圆角、间距以 UI 方案文件为准；实现时统一收敛到主题资源，便于后续调整。

### 6.2 任务标题与简介（历史会话列表）

- **标题**：10 字以内，取回答正文第一行。
- **简介**：20 字以内。
- **生成时机**：必须等该任务**回答结束**后才生成，回答过程中显示进行中文案。
- **不总结追问内容**：简介只根据首次回答生成，追问不会改动标题与简介。
- 失败/取消的任务显示对应状态文案（如「请求超时，可点击重试」）。

### 6.3 识别框任务队列中的回答展示

- 任务**完成**后，在任务标题下方用**小号文字显示回答输出的第一行**（与历史会话列表中的 20 字简介不同）。
- 默认只显示一行；标题行右侧提供**展开箭头**，点击后展开完整回答。
- 展开框中可**继续追问**（同详情页的追问能力，带上下文与原截图）。
- 展开框有**最大高度限制**，内容超出时内部滚动，不撑大整个队列面板。
- 处理中时，小号文字实时显示流式输出（末尾带光标），完成后固定为第一行。

### 6.4 各操作的回答模板

三类操作的回答格式不同，通过系统提示词约束：

- **问答**：
  - 第一行**直接输出答案**，简洁直接，不写「答案是」等前缀。
  - 换行后输出**解释**（可分段，可使用 Markdown）。
- **翻译**：
  - 第一行直接输出**完整译文**。
  - 换行后，对**重点短语或字词逐个换行**解释（每行一个词条）。
- **提取图文**：
  - 直接输出提取到的内容，不做任何额外说明、不加前缀、不用代码块包裹。

标题/首行展示统一依赖该格式：第一行即「答案 / 译文 / 提取正文」。

### 6.5 模型选择改为下拉框

> 本节已被 **8.2** 取代：识别框的「模型」菜单改为直接列出设置里已保存的模型配置，
> 不再向上游 `GET /models` 拉取。设置页的「拉取模型列表」仍保留上游拉取能力。

- 工具栏的「模型」按钮点击后，以**下拉框**形式列出可选模型，而不是逐个循环切换。
- 选项来源：**当前模型配置的 URL 上游已提供的模型列表**（即调用该接口的模型列表端点获取），而不是仅本地手工填写的模型名。

  - OpenAI 兼容：`GET {baseUrl}/models`
  - Claude：`GET {baseUrl}/v1/models`
  - Gemini：`GET {baseUrl}/v1beta/models`

- 下拉框需支持：加载中、加载失败（回退为本地已配置的模型名）、选中项高亮。
- 选中的模型立即用于后续任务，并持久化。

### 6.6 追问

- 详情页与识别框展开框都支持追问。
- 追问携带该任务的完整对话上下文；「追问时附带原截图」开关默认开启（详情页可勾选）。
- 追问内容不参与标题/简介生成。
- 追问过程中的流式输出实时显示，可中途停止。

### 6.7 UI 与交互细节（对应 UI 方案）

- 主程序、任务详情、设置均使用深色主题与自定义标题栏（最小化 / 最大化 / 关闭）。
- 识别框尺寸标签在拖动/缩放时实时显示宽高像素。
- 任务队列卡片：处理中卡片带琥珀色描边与流式文本光标；已完成卡片显示首行回答 + 展开箭头。
- 详情页顶部提供「重新回答」，AI 回复下方提供「复制」「重新回答」。
- 所有列表空状态需给出引导文案。

### 6.8 数据字段补充

- `tasks` 表增加 `first_line`（回答首行，用于识别框展开前的一行展示）。
- `messages` 表已有结构可承载追问多轮，无需新增表。
- 模型列表缓存不落库，内存缓存 10 分钟，切换配置或重启后重新拉取。

# 7. 第二轮修订（2026-10-28）

本节为 UI 走查后的修订，与前文冲突时以本节为准。

### 7.1 软件名称

软件名称统一为 **RegionX**（窗口标题、任务栏、托盘、开始菜单、安装包一律使用 RegionX）。
文档与代码中不再出现「区域识别助手」。

### 7.2 主题系统（可扩展）

- 现有「深色 + 琥珀」主题保留，新增「白色 + 蓝色」主题。
- 主题必须设计成**统一接口**，以后新增主题只需新增一份主题定义，不改界面代码：

  - 一个 `ITheme` 暴露一套语义化颜色令牌（背景、面板、卡片、描边、主文字、次文字、强调色、成功/警告/危险、截图纸色等）；
  - 主题注册表 `IThemeRegistry` 负责按名称查找、枚举全部主题；
  - 所有界面只引用**语义令牌**（DynamicResource），不写死颜色值；
  - 用户选择的主题持久化到设置，重启后恢复；切换主题立即全局生效。

- 主题清单：

  | 名称 | 背景 | 面板 | 强调色 | 说明 |
  |---|---|---|---|---|
  | 深色（默认） | `#17181C` | `#1D1F24` / `#212328` / `#2A2D33` | `#FFB224` 琥珀 | 原 UI 方案配色 |
  | 白色 | `#F7F8FA` | `#FFFFFF` / `#F1F3F6` | `#2F6FED` 蓝 | 白底蓝强调，深色文字 |

### 7.3 设置页可见性

- 设置页的输入框（接口类型、模型名等下拉框与文本框）文字颜色必须与主题匹配，
  深色主题下为浅色字，白底主题下为深色字，**不得出现黑底黑字 / 白底白字**。
- 模型名下拉框的每个选项左侧显示**该模型的品牌标识**（图标）。

### 7.4 模型品牌标识

- 模型列表（设置页下拉框、识别框模型菜单）每个选项左侧显示品牌图标。
- 识别规则：按模型名关键字匹配品牌，例如
  `deepseek`、`gpt`/`o`/`openai`、`claude`、`gemini`、`qwen`/`qwen`、`kimi`/`moonshot`、
  `glm`/`chatglm`、`llama`/`meta`、`mistral`、`grok`、`ollama`、`ernie`/`文心`、`doubao`/`豆包`。
- 未能识别的模型统一使用 **GPT 标识**作为默认。
- 图标以矢量资源内置，不依赖网络。

### 7.5 识别框与工具栏

- **识别框是独立窗口**：出现在任务栏（或至少可被窗口切换器找到），
  点击任务栏图标能直接找回识别框；主程序退出时所有窗口一并正常关闭。
- 工具栏第一个按钮文字由「回答」改为「**问答**」，样式与「翻译」一致：
  白色线条图标 + 黑灰背景（不再使用琥珀高亮填充）。
- 工具栏的「模型」按钮显示**设置里当前选中的模型名**，点击后弹出模型菜单：
  - 菜单选择一项后自动关闭；点击其他区域也会关闭；
  - 菜单项左侧的品牌图标区域**不应出现白色底块**（图标透明背景，随主题着色）。

### 7.6 任务队列

- 任务卡片高度约为原来的 **2/3**，宽度约为原来的 **4/5**（队列面板相应变窄）。
- 修复任务卡片展开后**追问输入框无法输入文字**的问题。
- 去掉任务卡片上的「详情」按钮（展开箭头已承载该能力）。
- 卡片标题 = 该任务建立后生成的总结（10 字以内）；小号字 = AI 回复第一行。

### 7.7 主程序历史会话

- 点击任务**不再弹独立窗口**，改为在**主程序原窗口内**展示任务详情
  （右侧或下部详情区，可返回列表）。
- 会话的展开箭头必须随展开 / 收回**实时翻转方向**。
- 历史会话里任务的小号字与任务队列统一：**AI 回复的第一行**（不是 20 字简介）。
  任务标题也统一为 10 字以内总结。

### 7.8 识别框交互

- 拖动更易触发：识别框**整条边框**（含上下左右四边）都可拖动移动，
  不必精确点中 2px 边框内侧。
- 四角仍保留缩放手柄，拖角改变大小。

### 7.9 数据字段

- `settings` 增加主题名（`ThemeName`）。
- 任务卡片与历史列表共用 `title`（≤10 字）与 `first_line`（AI 回复首行）。

# 8. 第三轮修订（2026-10-29，实测走查）

### 8.1 识别框拖动与缩放

- 四条边（上下左右）整条 10px 都是**拖动移动**热区，四角 24px 命中区用于**缩放**。
- 注意层级：四角手柄必须**声明在**四条边热区之后（更靠上层），
  否则边会盖住角，导致拖角缩放触发不了。
- 四边热区在角两侧各让出 14px，避免与角抢操作。
- 实测：拖任一角改变宽高（570×300 → 490×240 → 501×310），拖任一条边只移动、不改尺寸。

### 8.2 识别框「模型」菜单

- 菜单内容 = **设置里已保存的模型配置列表**，不再向上游拉取模型列表逐个罗列。
- 每项：左侧**该配置模型名对应的品牌图标**；主文本为**配置名称**；
  配置名与模型名不同时，下方小字显示模型名。
- **当前在用的配置**整行使用强调色，并在**右侧显示对勾**；未选中的项右侧留空以保持左对齐。
- 选择一项只切换「当前模型」，不修改该配置已保存的模型名。
- 底部保留「在设置中配置模型…」入口。

### 8.3 主程序页边距

- 主程序内容区左右页边距由 40px 收窄到 24px，上边距 36px → 20px，
  内容最大宽度 880px → 1040px；底部「开始识别」区上下留白相应收紧（20/24 → 14/18）。
- 任务详情页内边距同步收紧：标题行 32,16 → 24,12；内容区 32,28 → 24,20；底部输入区 32,12,32,24 → 24,10,24,18。

### 8.4 任务队列展开

- 卡片展开后**隐藏**标题下方那行「回答首行」，避免与正文第一行重复；
  完整回答、追问轮次与追问输入框照常显示。

### 8.5 主题令牌补充

- 识别框拖动热区的透明命中色收敛为语义令牌 `HitTestBrush`
  （深色/白色主题各一份），界面不再出现写死的颜色值。
- 状态浅色底补充 `SuccessSoftBrush` / `WarningSoftBrush` / `DangerSoftBrush`，
  `StateToSoftBrush` 转换器改为按主题令牌取色（此前写死浅色，深色主题下不成立）。

### 8.6 托盘与主窗口关闭（8.6～8.9 为第四轮修订）

- 主窗口的「关闭」按钮**不再退出程序**，只隐藏到托盘；识别框、任务队列照常工作。
- **单击或双击托盘图标**都能把主窗口唤回（此前双击时窗口已销毁，会抛
  「关闭窗口后无法设置可见性」并弹错误框）。
- 真正退出只有两条路：托盘右键菜单「退出」，或系统关机；此时主窗口允许关闭。
- 唤回时先置顶再取消置顶，保证窗口盖在其他窗口之上。

### 8.10 上游配置的添加与模型拉取（第五轮修订）

背景：旧版「拉取模型列表」只按固定路径拼接地址，且模型名在未拉取时不可手填，
导致「新上游存不下来」「按 URL 取不到模型」。本轮修复：

- **模型名始终可手填**：设置页的模型名改为普通输入框 + 「选择」按钮。
  输入框的内容直接决定保存结果，不再依赖是否拉取过列表。
  点「选择」弹出模型列表（左侧品牌图标、当前项打勾），选中即回填。
- **保存校验放宽**：模型名非空即可保存；Base URL 可留空（用官方地址），
  填了就必须是 `http://` / `https://` 的绝对地址，三种接口类型统一校验。
  此前只校验了 OpenAI 兼容类型，且模型名为空时一律拒绝保存。
- **按 URL 取模型更宽容**：`ModelCatalog` 会依次尝试多个候选地址，
  只有 404 / 405 才换下一个，认证类错误立即抛出：

  | 接口类型 | 候选顺序 |
  |---|---|
  | OpenAI 兼容 | `{base}/v1/models` → `{base}/models` → `{base}/openai/v1/models` |
  | Claude | `{base}/v1/models` → `{base}/models` |
  | Gemini | `{base}/v1beta/models` → `{base}/models` |

  - 只填主机名（如 `https://api.example.com`）时自动补 `/v1` 等路径；
  - 误把完整端点（`/chat/completions`、`/messages`、`/models`）粘进来时，
    会先剥离再拼模型列表地址；
  - 拉取列表时一并带上「自定义请求头」，需要特殊头的网关不再 401/403。
- **拉取后不覆盖手填值**：仅当模型名为空时才用列表第一项兜底。
- 已删除历史遗留的测试用上游配置，当前无任何上游配置，首次使用需重新添加。

### 8.11 配置持久化与保存反馈（2026-10-29 修订）

- 「设为当前模型」会先保存当前配置，避免引用未保存的新模型。
- 上游列表去重后按模型名忽略大小写排序；已保存模型列表同样按模型名排序。
- 本轮以自动化测试验证配置文件独立恢复、旧库迁移、失败重试和 WPF 资源加载与渲染；此前将 WAL 本身归因为配置丢失的说法未获本轮证据支持。
